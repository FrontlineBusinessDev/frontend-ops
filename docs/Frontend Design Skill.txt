## 🎨 Taste & Aesthetic Directives (Anti-Slop Framework)
When styling the component (using Tailwind CSS or standard CSS modules), strictly adhere to the following design principles:

*   **Typography:** Avoid default generic sans-serifs unless intentionally styled. Create a distinct typographic hierarchy. Mix font weights deliberately (e.g., medium/semibold for micro-copy, tracking-tight for display headings, or mono fonts for technical accents). You may use poppins
*   **Color & Contrast:** Reject pure black (`#000000`) and pure white (`#FFFFFF`). Use rich, tinted darks (e.g., `zinc-900`, `slate-950`) and soft off-whites (`zinc-50`). If using accent colors, opt for sophisticated, muted palettes with high-contrast foregrounds. You may use the color in logo i provided as color theme.
*   **Spacing & Density:** Reject generic `p-4 m-4` uniformity. Use intentional whitespace, generous padding for outer containers, and tight, cohesive spacing for grouped UI elements. Readability and visual breathing room are paramount.
*   **Borders & Depth:** Use ultra-subtle borders (e.g., `border-white/10` in dark mode or `border-black/5` in light mode). Use layered, diffuse shadows for depth rather than harsh, default drop-shadows.
*   **Motion & Interaction:** Include subtle, physical micro-interactions for hover/focus states (e.g., slight opacity shifts, sub-pixel transforms). Use smooth easing curves (e.g., `cubic-bezier(0.32, 0.72, 0, 1)`). **Never** use aggressive, bouncy, or gratuitous animations.

## ⚙️ Technical Architecture (React + TypeScript)
Ensure the component is robust, highly reusable, and follows modern frontend best practices:

*   **Strict Typing:** Define a comprehensive, exported `interface` for the component's `Props`. Always extend native HTML element props (e.g., `React.ComponentPropsWithoutRef<'button'>`) where applicable to ensure standard HTML attributes pass through.
*   **Ref Forwarding:** Wrap the primary DOM element in `React.forwardRef` to allow consuming applications to control the DOM node or manage focus.
*   **Class Merging:** Include a `className` prop. Use a utility like `clsx` and `tailwind-merge` (or template literals if libraries are unavailable) to allow consumers to cleanly override or extend styles without conflicts.
*   **Compound Components (If Applicable):** If the requested component contains multiple complex parts (e.g., a Card, Modal, or Select), structure it using the compound component pattern (e.g., `<Card>`, `<Card.Header>`, `<Card.Content>`).
*   **Accessibility (a11y):** Bake in native accessibility. Include necessary `aria-*` attributes, ensure logical keyboard navigation, and manage visible focus states properly (e.g., `focus-visible:ring-2 focus-visible:ring-offset-2 focus:outline-none`).
